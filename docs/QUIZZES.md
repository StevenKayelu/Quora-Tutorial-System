# Quiz routes and student email flow

**Audience access:** the editor defaults to Active subscribers only and offers All student accounts or Custom audience. Custom selections combine individual students OR students at selected course-offering schools OR optional active subscribers. Custom study years narrow only the selected school groups. Counts, non-subscriber totals and a short preview make the effect visible. School choices use actual main/shared offering links from the backend, not student membership. See [audience policy and tests](../../backend/docs/QUIZ_AUDIENCES.md).

If Audience is disabled, the section now explains whether the quiz is locked or the account lacks permission. For a closed/published quiz, eligible admins can click **Edit audience → Return to draft** directly in the editor, select **All student accounts**, save, then publish a new version. The editor focuses the audience selector after unlocking. The confirmation pauses new starts until republication and preserves existing attempts/results. Cancelling or a failed request leaves editing locked. Withdrawing a published quiz also requires publish permission.

Quiz pages now share a compact header and the application's existing panel/theme. Advanced settings, detailed statistics and delivery history are collapsible. All application browser confirmations have been replaced with MUI dialogs, including result release, course changes, leaving a quiz and term deletion. Browser-controlled close/refresh protection remains native. Release confirmation freezes the publication version shown to the admin.

Question upload uses a course-aware dialog: download an Excel/CSV template, choose a file for automatic validation, review sample questions/answers and import. IDs are filled from the selected course, and the Excel workbook includes instructions and an actual Course IDs reference. Imports inside the editor attach the new questions automatically. See [the file format guide](../../backend/docs/QUIZ_IMPORT_GUIDE.md).

Quiz management actions now use an accessible MUI confirmation dialog instead of native browser prompts. Publishing shows the quiz/course, question count, duration, opening/closing dates and notification details; scheduled publications use Schedule quiz. Cancel makes no request, controls remain disabled while saving, and a failed request stays in the dialog for retry.

Student cards and instructions show a live Starts in countdown for scheduled quizzes, Closes in for an available quiz with a closing date, or Time remaining for an active attempt. These update once per second from the latest server timestamp using a monotonic browser clock, without additional API polling. Availability changes at the opening/closing boundary without requiring a refresh. Opening never starts an attempt automatically; the student must acknowledge and press Begin quiz. Active attempts now display larger Quiz time remaining and Question time remaining counters, retaining server deadline enforcement and automatic finalization.

Admin navigation and the admin dashboard open `/admin/quizzes`. Management supports drafts, question-bank versions, ordering, randomized pools, CSV/XLSX validation/import, timing, schedules, course/cohort/student assignments, preview, duplication, publishing, closing and archiving. `/admin/quizzes/new` and `/admin/quizzes/:quizId/edit` are the editor; `/admin/quizzes/:quizId/results` provides monitoring, filtered export, result release, attempt/integrity review and individual time/retake/accessibility overrides.

Under **Timing & scoring**, admins enter **Number of questions** and **Minutes per question**. New quizzes automatically calculate the overall duration: 20 questions × 2 minutes shows 40 minutes, even while planning questions still to be added. Publishing requires at least the requested number of actual questions. A larger selected pool provides a random sample; differing individual limits show a duration range. Each attempt receives its exact sampled total. Existing quizzes retain their manual overall limit until edited and republished. A separate overall limit remains available in the Quiz duration selector. See [automatic timing and the 500-student local test](../../backend/docs/QUIZ_TIMING_AND_LOAD.md).

Student navigation and the student dashboard open `/user/quizzes`. Email links and the notification bell open `/user/quizzes/:quizId`. Students acknowledge rules before starting. `/user/quizzes/attempts/:attemptId` is an authenticated examination screen outside the dashboard layout, and `/user/quizzes/attempts/:attemptId/result` is the result/review screen.

The admin marks one correct option in each bank question; submission/timeout grading is automatic. In the quiz editor, Allow answer review, Show correct/wrong for each question, Show correct answers, Show explanations and Allow student PDF downloads control student review. Result release controls when review and downloads become available. Outcomes can be shown while the correct option remains hidden. Students see their name/ID and can download a branded script from the result page when permitted. Admin Results offers Download results PDF for all filtered pages; individual attempt review offers Download marked script PDF. See [PDF report setup and samples](../../backend/docs/QUIZ_PDF_REPORTS.md).

`ProtectedRoutes` preserves pathname, query and fragment when directing a signed-out visitor to login. `Login` uses `getLoginDestination` to return only to a local route belonging to the signed-in role. The query parameter preserves the destination if the login page is refreshed. A quiz link never substitutes for authentication or starts the timer. Existing email verification is still required by the authentication service.

API calls use the existing Axios/token handling. Quiz query caches and pending-answer recovery data are scoped to the account, avoiding reuse across sign-ins. Answers save on selection; a pending selection is held in session storage and retried after a connection failure, subject to server deadlines. A selection made during background synchronization remains queued. Only one request mutates an attempt at a time in the interface, and the server independently locks/validates attempts. The displayed timers use server timestamps and a monotonic browser clock. A displayed deadline triggers synchronization to advance the question or finalize/navigate to results; 5-second recovery polling also continues. Refresh does not reset timers; overdue attempts finalize on the server even when the browser is closed.

Configure `VITE_API_BASE_URL` as before, and ensure optional `VITE_BASENAME` corresponds to the backend's `VITE_PUBLIC_URL` path. Deploy the backend and migration 007 before enabling these routes. The quiz feature adds no runtime packages. Source types and shared API/review helpers live in `src/features/quizzes`. Backend setup, endpoint contracts, data policies and rollback are documented in the backend repository's `docs/QUIZZES.md`.

Verification commands: `node_modules/.bin/tsc --noEmit`, `npm run build`, and ESLint on the new quiz directories. The backend's `tests/quiz-browser.mjs` provides desktop/mobile browser flows against a local built preview with isolated API fixtures. See the workspace `QUIZ_IMPLEMENTATION.md` for checks completed and remaining environment limitations.
